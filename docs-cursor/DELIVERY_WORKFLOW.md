# 交付流程（DELIVERY WORKFLOW）

## 1. 目标

建立可重复执行的交付流程，确保每次推进都"可见、可验、可回退"。

## 2. 标准流程（单任务）

1. **定义任务**
   - 明确任务目标、范围、输入依赖、验收标准。
2. **接口与约束确认**
   - 确认接口契约（路径 / 参数 / 响应 / 错误码），记录在 `API_CONTRACT.md`。
   - 确认是否触发高风险事项（升级、重构、配置变更）。
3. **实施**
   - 只做当前任务范围内改动。
   - 保持小步提交与中间可运行状态。
4. **验证**
   - 执行最小验证清单并记录结果。
5. **交付记录**
   - 输出：改动点、验证步骤、结果、已知问题、下一步建议。

## 3. 任务卡（必须）

每个任务按 `TASK_TEMPLATE.md` 格式记录，存放在 `tasks/` 目录。

## 4. 门禁规则

- 未定义验收标准，不开始实施。
- 未完成验证，不算任务完成。
- 出现阻塞超过 30 分钟，必须输出"阻塞原因 + 两个备选方案"。
- 禁止在同一任务混合以下变更：
  - 功能开发
  - 依赖升级
  - 大规模重构

## 5. 阶段划分

- **Phase 0**：治理基线（规则与文档模板）
- **Phase 1**：主链路联调（登录 → 核心功能）
- **Phase 2**：稳定化（回归测试、错误收敛、文档完善）
- **Phase 3**：升级规划（依赖升级专门阶段）

## 6. 每日推进节奏

- 开始前：确认当天任务卡与验收标准
- 执行中：同步关键进度与风险
- 结束前：提交当日记录（完成项 / 未完成项 / 阻塞 / 次日计划）

## 7. 输出物规范

每次任务结束必须至少输出：

- 改动文件列表
- 可复现验证步骤
- 预期结果与实际结果
- 已知问题（若有）
- 下一个最小任务建议
