# 交付流程

## 核心原则：先读代码，再写代码

```
传统方式：你整理接口文档 → 我按文档写代码
Claude Code 方式：我读后端代码 → 我提取契约 → 我写代码 → 你验证结果
```

---

## 每个功能模块的标准流程

### 1. 探索阶段（我来做）

开始写代码之前：
- 读后端相关模块，确认：路由路径、HTTP 方法、必填参数、响应字段、可能的错误码
- 看设计稿/原型对应页面（如有），确认布局和交互逻辑
- 发现设计与后端数据不一致 → 立即说明，给出处置建议，等你确认

### 2. 实现阶段

- 先写接口调用层（composables / hooks / services）
- 再写页面/组件
- 写完后重读一遍，主动发现问题

### 3. 交付

每次完成后我会输出（不需要你问）：

**改动了什么**
```
path/to/file.ts     新建 / 修改，一句话说明做了什么
```

**怎么验证**（可直接操作的步骤，不是描述性文字）
```
1. 启动命令
2. 打开 URL
3. 执行操作 → 期望看到什么
```

**发现的问题**（即使超出当前范围也列出）

---

## 阻塞时怎么办

我会先自己尝试：
- grep 后端代码找类似逻辑
- 读相关模型文件理解数据结构
- 尝试降级实现（mock 数据 / 跳过可选功能）

如果仍然阻塞，我会给你：**阻塞原因 + 两个备选方案**，而不是无限等待或不断重试。

---

## 什么情况下我会暂停等你确认

- 删除文件或目录
- 修改数据库相关代码
- 发现设计与后端差异较大，需要决策
- 要改一个影响面不确定的文件
